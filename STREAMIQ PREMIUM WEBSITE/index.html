BUSINESS QUESTIONS SQL → ANSWERS

QUESTIONS THE
DATABASE CAN ANSWER

Practical analytics, expressed as queries against a connected streaming model.

01

Which content has the highest engagement?

AVG(completion_percentage)
GROUP BY content_id
ORDER BY completion DESC
02

Which plans generate the most revenue?

SUM(successful payments)
GROUP BY plan_name
ORDER BY revenue DESC
03

How many subscriptions were cancelled?

COUNT(CASE WHEN status =
'CANCELLED' THEN 1 END)
— subscription rate, not churn
04

Which devices consume the most watch time?

SUM(watch_duration_minutes)
GROUP BY device_type
ORDER BY minutes DESC
05

Which genres receive the highest ratings?

AVG(rating)
JOIN content_genres
GROUP BY genre_id
06

Which profiles are the most engaged?

SUM(watch minutes)
COUNT(DISTINCT content_id)
GROUP BY profile_id
07

How does watch completion vary by content?

AVG(completion_percentage)
GROUP BY content_id
COMPARE by content type
08

Which users resubscribed after cancellation?

LAG(subscription_status)
OVER (PARTITION BY user_id
ORDER BY start_date)
CONTENT ENGAGEMENT QUERY MYSQL
SELECT
    c.title,
    AVG(wh.completion_percentage) AS avg_completion
FROM content c
JOIN watch_history wh ON c.content_id = wh.content_id
GROUP BY c.content_id, c.title
ORDER BY avg_completion DESC;

BUILT FOR PERFORMANCE

EXPLAIN confirms the intended composite index is selected for profile-specific viewing history.

streamiq / explain_analysis.sqlMYSQL 8.0
-- Indexes created for common access patterns
CREATE INDEX idx_watch_profile_start
  ON watch_history(profile_id, watch_start);

CREATE INDEX idx_watch_content
  ON watch_history(content_id);

CREATE INDEX idx_payments_date_status
  ON payments(payment_date, payment_status);

EXPLAIN SELECT profile_id, watch_start
FROM watch_history WHERE profile_id = 1
ORDER BY watch_start;
